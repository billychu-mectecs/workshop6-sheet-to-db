# 目前作品：上週的 Sheet 版本

## 使用者看到什麼

1. 開啟飲料訂購頁面。
2. 選擇飲料並輸入姓名。
3. 系統扣除剩餘數量並新增一筆訂單。
4. 使用者可以取消訂單或重設練習資料。

## 資料目前怎麼走

```text
使用者畫面
  -> Python 程式
  -> Google Sheet 的庫存表與訂單表
```

Google Sheet 很適合快速做出第一版，也方便人工查看。但這個作品開始多人共同使用後，會遇到幾個問題：

- 兩個人同時搶最後一杯，扣庫存與新增訂單可能只成功一半。
- 列的位置改變後，原本用列號辨識訂單的方式容易出錯。
- 誰能看、誰能改，以及修改紀錄不容易跟部門權限完整配合。
- 程式、資料與憑證若綁在個人電腦，換電腦或電腦故障時不容易接手。

Workshop 6 不否定 Sheet。一般清單、人工整理與短期資料仍可使用 Sheet；這次要搬的是「系統每天會讀寫、多人共同使用、需要長期保留」的核心資料。

## 這次要變成什麼

```text
使用者畫面
  -> Python 程式
  -> 部門資料庫
```

資料庫放在可共同使用的環境中，程式透過個人 SQL Login 取得自己的使用範圍。每位學員只能在所屬部門資料庫中的個人工號 schema 建立與操作資料表，不能任意查看其他部門或其他學員的資料。
