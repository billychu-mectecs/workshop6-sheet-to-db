# 飲料訂購資料字典

這是給人與 AI 共用的白話規格。資料表與欄位的實際名稱可依專案既有慣例調整，但規則不可遺失。

## 飲料品項

| 資料 | 用途 | 規則 |
|---|---|---|
| 品項編號 | 穩定辨識一種飲料 | 不可重複 |
| 品項名稱 | 畫面顯示 | 不可空白 |
| 總庫存 | 本輪可供應數量 | 不可小於 0 |
| 剩餘庫存 | 還能訂購的數量 | 介於 0 與總庫存之間 |
| 圖示與說明 | 畫面顯示 | 可空白 |
| 最後更新時間 | 追蹤資料變更 | 由系統記錄 |

## 訂單

| 資料 | 用途 | 規則 |
|---|---|---|
| 訂單編號 | 穩定辨識一筆訂單 | 不可重複，不使用 Sheet 列號 |
| 訂購時間 | 保留發生順序 | 使用台北時間 |
| 訂購人 | 畫面顯示 | 練習時只用假姓名 |
| 品項編號 | 連到飲料品項 | 必須存在 |
| 狀態 | 分辨有效或已取消 | 至少包含「有效」「已取消」 |
| 取消時間 | 知道何時取消 | 未取消時可空白 |

## 必守工作規則

- 剩餘庫存為 0 時不能再下單。
- 下單的扣庫存與新增訂單必須一起成功。
- 取消有效訂單時恢復一份庫存，且不可重複恢復。
- 取消保留紀錄，不直接讓歷史消失。
- 搬遷重跑時不能產生重複訂單。
