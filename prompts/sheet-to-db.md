# 萬用 Prompt：請 AI 把 Sheet 版作品搬到資料庫

把下面整段交給 AI。AI 應先說明計畫，等你確認後才開始修改。

```text
你是我的 AI 開發特助。請依照官方參考 Repo 的 README.md 與 CLAUDE.md，把我啟動 Claude Code 時所在的既有作品，從 Google Sheet 改成使用課堂提供的 SQL Server 資料庫。官方 Repo 只提供規則與範例，不是要修改或直接覆蓋的成品。

我的目標：
- 保留現在的畫面與主要操作方式。
- 將這個作品會持續累積、需要多人共同使用的資料搬到資料庫。
- 資料不因個人電腦故障或檔案被改壞就消失。
- 我不用學 SQL，也不需要知道帳號密碼。

開始前：
1. 分別確認我的既有專案與官方參考 Repo 的位置；真正修改的只能是我的既有專案。
2. 先讀懂我的整個專案，不要先執行或修改，也不要用官方範例覆蓋我的檔案。
3. 第一題只問我：「你是哪個部門？」回答只用來確認，真正權限仍以 Windows 身分與資料庫授權為準。
4. 依 docs/connection-flow.md 檢查連線環境。不要問我主機、帳號、密碼或 connection string，也不要顯示環境變數的實際值。
5. 用白話告訴我目前資料從畫面到 Google Sheet 的流程。
6. 比對官方範例後，列出我的作品中哪些 Sheet、欄位與功能會搬到資料庫，以及哪些既有修改會保留。
7. 一次問我一個必要的工作規則；能從現有程式確認的就不要再問。
8. 提出分階段計畫與每階段的驗收方式，等我確認。

執行時：
1. 先保留我的既有作品與可回復的原始版本，建立 Git 修改紀錄。
2. 只從 WORKSHOP6_SQL_SERVER、WORKSHOP6_SQL_DATABASE、WORKSHOP6_SQL_SCHEMA、WORKSHOP6_SQL_AUTH 取得非秘密連線設定。
3. 使用 Windows 登入身分連線，不向我索取或顯示帳號密碼。
4. 在我的 schema 內建立資料表與 migration，不操作其他資料庫或 schema。
5. 先用少量假資料測試，再搬入我的練習資料；搬遷不可製造重複資料。
6. 訂購時，檢查庫存、扣庫存、新增訂單必須一起成功或一起取消。
7. 取消訂單要保留紀錄並恢復庫存；清空全部資料前再次問我。
8. 保留我原本改過的畫面、文字、功能與 API 使用方式，補上必要的錯誤提示與測試。

完成後：
1. 讓我實際完成新增訂單、售完阻擋、取消訂單與重新開啟系統後資料仍存在。
2. 核對搬遷前後筆數、重複筆數、失敗筆數，清楚說明結果。
3. 掃描 Git 內容，確認沒有密碼、Token、憑證、真實資料、內部位址或 .env。
4. 用白話整理本次修改與 Git 紀錄。
5. 未經我確認，不要公開或上傳 GitHub。

若環境變數不存在、權限不符或你無法確定目標範圍，請停止並告訴我需要講師協助的項目，不要猜。
```

## 讓 Prompt 更精準的四句話

完成第一次改造後，可以再補充：

1. 背景：誰在什麼情況下使用？
2. 目標：希望哪件麻煩事變簡單？
3. 規則：哪些事情一定要遵守？
4. 驗收：看到什麼結果才算完成？

範例：「行政同仁每天替大家登記飲料。希望兩個人同時點最後一杯時不會超賣；取消要補回庫存；我能重新開啟系統看到剛才的訂單，就算完成。」
