# Workshop 6：把上週作品接到資料庫

這是 Workshop 6 的課堂參考專案。你真正要修改的，是自己上週完成的「飲料訂購系統」；這個 GitHub 專案只提供任務說明、規則與假資料，不會覆蓋你的作品。

你不需要學 SQL，也不需要知道資料庫帳號密碼。今天只要依序把四段任務說明交給 Claude，每一段完成後先確認，再進下一段。

Claude Code 是能讀懂整個作品資料夾、協助你修改與測試的 AI 特助。你今天只要做三件事：**開對自己的作品、一次貼一段任務、親自確認結果。**

## 為什麼這次要搬到資料庫

- **Google Sheet 像大家一起編輯的表格。** 很適合快速做出第一版，也方便人工查看。
- **資料庫像系統共用的資料倉庫。** 它能替每天累積的資料守住規則，讓多人同時使用，也不會因某一台電腦故障就失去全部紀錄。
- **今天不是學資料庫指令。** 你只要告訴 Claude 工作規則、確認畫面與結果，技術操作交給 AI。

這次飲料訂購系統會搬的是「系統每天要讀寫、多人會一起使用、需要長期保留」的訂單與庫存；一般清單或臨時整理仍然可以繼續使用 Sheet。

今天先在每個人的練習資料區完成，不使用公司真實資料。等大家熟悉後，才會進到部門共用環境，讓同一部門一起維護與延續作品。

## Git 與 GitHub，先記這兩句

- **Git：像遊戲存檔。** 它在你的電腦裡記住修改前後，改錯時比較容易找回來。
- **GitHub：線上作品資料夾。** 它集中放程式、說明與修改紀錄，方便分享與交接。

今天會從講師的 GitHub 取得任務說明，再用自己電腦裡的 Git 保存作品。第 2 段不會把你的作品上傳網路；是否上傳 GitHub，要等確認沒有帳密、公司資料與內部設定後再決定。

## 先確認這個 GitHub 專案能不能使用

GitHub 上有很多好工具，也可能有仿冒或危險內容。課堂先檢查四件事：

> Repo（專案資料夾）是 GitHub 對一份作品及其說明文件的稱呼。

- 網址與帳號是不是講師指定的。
- README（專案說明）有沒有清楚說明用途與操作方式。
- 最近是否仍有更新。
- 先請 AI 檢查有沒有可疑下載、外傳資料或索取帳密的行為。

Stars 像收藏或人氣票數，只能表示受到關注，不代表安全、品質好或適合公司使用。

## 今天依序貼四段，不要一次全部貼完

| 段落 | 你只要做什麼 | 完成後要看到什麼 |
| --- | --- | --- |
| [第 1 段：恢復作品](prompts/01-restore-project.md) | 讓上週作品正常開啟 | 能新增一筆假訂單，取消後庫存恢復 |
| [第 2 段：Git 存檔](prompts/02-git-checkpoint.md) | 留下改造前的安全存檔點 | AI 說明保存與排除的檔案 |
| [第 3 段：分析搬法](prompts/03-plan-sheet-to-db.md) | 找出 Sheet、欄位與工作規則 | 搬移計畫符合你的作品 |
| [第 4 段：搬移與驗證](prompts/04-migrate-and-verify.md) | 少量測試、完整搬移、比較前後差異 | 先確認少量測試，再確認最後結果 |

每段最後都會請 Claude 停下來。你確認沒有問題，再開下一段。

分成四段不是增加工作，而是讓你在每個重要步驟都有機會喊停，避免 AI 一次改太多卻不知道從哪裡檢查。

> **第 4 段會停兩次。** 第一次看到少量測試的成功、重複與失敗筆數後，在同一個 Claude 對話回答「可以」；Claude 才會繼續完整搬移。第二次才是整個任務完成。

## 課堂怎麼開始

1. 行前會已執行個人安裝包中的 `Setup-Claude.bat`，而且桌面已有 Claude 捷徑的人，不用重裝。尚未完成的人先請講師協助，看到 `Setup complete` 才繼續。
2. 在「自己上週完成的作品資料夾」開啟 Claude Code。
3. 點開 [第 1 段任務說明](prompts/01-restore-project.md)，使用灰色文字框右上角的複製按鈕，把整段貼給 Claude Code。
4. 作品能正常開啟後，再依序進行第 2、3、4 段。

## 這堂課會完成什麼

- 保留目前能用的飲料訂購畫面與原始 Sheet。
- 把訂單、品項與庫存搬到個人練習資料庫。
- 確認同一筆訂購不會重複扣庫存或超賣。
- 核對搬移前後的資料筆數與主要功能。
- 用 Git 保存改造前與改造後的版本，讓 AI 說明差異。

簡單分工：**今天從 GitHub 取得講師任務，用 Git 在自己的電腦存版本；資料庫保存作品每天累積的資料。**

## AI 如何使用安全資料庫連線

這一段是給 AI 讀的，學員不用操作。你只需要確認 Claude 最後回報「已連到你的個人練習資料庫」。不用輸入部門、工號、主機、帳號或密碼，也不要把任何秘密貼進對話。

AI 必須依 [安全連線規則](docs/connection-flow.md) 操作，只能使用安裝包已核發的個人練習範圍。若連線不完整或權限不符，Claude 必須停止並請講師協助。

## 公開專案不可放的東西

- 密碼、API Key、Token、憑證檔與 `.env` 實際內容。
- 公司內部位址與完整資料庫連線資訊。
- 真實員工、客戶、訂單或營運資料。
- 未經公司同意的文件與程式。

本專案只使用假資料與欄位名稱。實際連線由每台電腦的安全環境提供。

## 專案內容

以下主要是給 AI 參考，學員不需要逐一打開：

- `app.py`、`index.html`：上週 Sheet 版飲料訂購系統的公開範例。
- `CLAUDE.md`：AI 必須遵守的課堂與安全規則。
- `prompts/`：學員依序複製的四段任務說明。
- `docs/current-system.md`：目前作品的白話說明。
- `docs/data-dictionary.md`：資料欄位與規則。
- `docs/connection-flow.md`：AI 使用的安全連線流程。
- `sample-data/`：可公開使用的假資料。
- `migrations/`：AI 保存資料庫改造步驟的位置，方便以後重做或交接。

## 進階：以後參考或公開專案時

- README 是否說明用途、安裝與使用方式。
- `.gitignore` 是否排除 `.env`、金鑰、密碼、Token 與憑證。
- 公開內容是否沒有公司機密、個資或真實營運資料。
- License（使用授權）是否清楚；沒有授權不代表可以任意使用。
- Issues（問題回報）是否有人處理，Releases（整理好的版本）是否穩定。
- 修改紀錄標題是否看得懂，是否避免把大型檔案直接放進 Git。
- 團隊正式專案是否透過工作分支與合併前檢查，不直接在正式版本試錯。

> 本專案是課堂起點，不含公司正式環境，也不是可直接部署的正式系統。
