# Workshop 6：把上週作品接到資料庫

這是 Workshop 6 的課堂參考專案。你真正要修改的，是自己上週完成的「飲料訂購系統」；這個 GitHub 專案只提供任務說明、規則與假資料，不會覆蓋你的作品。

你不需要學 SQL，也不需要知道資料庫帳號密碼。今天只要依序把四段任務說明交給 Claude，每一段完成後先確認，再進下一段。

## Git 與 GitHub，先記這兩句

- **Git：像遊戲存檔。** 它在你的電腦裡記住修改前後，改錯時比較容易找回來。
- **GitHub：線上作品資料夾。** 它集中放程式、說明與修改紀錄，方便分享與交接。

今天一定會使用本機 Git；是否把作品上傳 GitHub，要等確認沒有帳密、公司資料與內部設定後再決定。

## 先確認這個 GitHub 專案能不能使用

GitHub 上有很多好工具，也可能有仿冒或危險內容。課堂先檢查四件事：

- 網址與帳號是不是講師指定的。
- README（專案說明）有沒有清楚說明用途與操作方式。
- 最近是否仍有更新。
- 先請 AI 檢查有沒有可疑下載、外傳資料或索取帳密的行為。

Stars 像收藏或人氣票數，只能表示受到關注，不代表安全、品質好或適合公司使用。

## 課堂怎麼開始

1. 若尚未安裝資料庫連線，解壓講師提供的個人安裝包，雙擊裡面的 `install-db-access.bat`。看到安裝成功即可關閉。
2. 在「自己上週完成的作品資料夾」開啟 Claude Code。
3. 複製並送出 [第 1 段任務說明](prompts/01-restore-project.md)。
4. 作品能正常開啟後，再依序進行第 2、3、4 段。

## 這堂課會完成什麼

- 保留目前能用的飲料訂購畫面與原始 Sheet。
- 把訂單、品項與庫存搬到個人練習資料庫。
- 確認同一筆訂購不會重複扣庫存或超賣。
- 核對搬移前後的資料筆數與主要功能。
- 用 Git 保存改造前與改造後的版本，讓 AI 說明差異。

簡單分工：**GitHub 保存作品怎麼做；資料庫保存作品每天累積的正式資料。**

## AI 如何使用安全資料庫連線

這一段是給 AI 讀的，學員不用操作。安裝後的連線工具位於：

```text
%LOCALAPPDATA%\Medtecs\DbAccess
```

AI 必須依 [docs/connection-flow.md](docs/connection-flow.md) 使用安全連線，只能操作核發給這位學員的個人練習資料區。不得顯示、複製或把帳密寫進作品、Git 或對話。

## 公開專案不可放的東西

- 密碼、API Key、Token、憑證檔與 `.env` 實際內容。
- 公司內部位址與完整資料庫連線資訊。
- 真實員工、客戶、訂單或營運資料。
- 未經公司同意的文件與程式。

本專案只使用假資料與欄位名稱。實際連線由每台電腦的安全環境提供。

## 專案內容

- `app.py`、`index.html`：Sheet 版飲料訂購系統範例。
- `CLAUDE.md`：AI 必須遵守的課堂與安全規則。
- `prompts/`：四段任務說明，以及舊連結的導覽頁。
- `docs/current-system.md`：目前作品的白話說明。
- `docs/data-dictionary.md`：資料欄位與規則。
- `docs/connection-flow.md`：AI 使用的安全連線流程。
- `sample-data/`：可公開使用的假資料。
- `migrations/`：AI 放置資料庫改造紀錄的位置。

## 進階：以後參考或公開專案時

- README 是否說明用途、安裝與使用方式。
- `.gitignore` 是否排除 `.env`、金鑰、密碼、Token 與憑證。
- 公開內容是否沒有公司機密、個資或真實營運資料。
- License（使用授權）是否清楚；沒有授權不代表可以任意使用。
- Issues（問題回報）是否有人處理，Releases（整理好的版本）是否穩定。
- 修改紀錄標題是否看得懂，是否避免把大型檔案直接放進 Git。
- 團隊正式專案是否透過工作分支與合併前檢查，不直接在正式版本試錯。

> 本專案是課堂起點，不含公司正式環境，也不是可直接部署的正式系統。
